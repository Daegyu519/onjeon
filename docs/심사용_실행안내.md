# 온전(穩全) — 프로토타입 실행 안내

> KB Future Finance A.I. Challenge 제8회 · 예선 제출물 「첨부3. 프로토타입(개발 코드)」
> 이 파일은 제출 zip의 `03_프로토타입/README_심사용.md`로 들어간다.

**"이 집, 위험을 감안하면 전세가 월세보다 정말 싼가?"** — 등기부등본 한 장을 읽어
보증금 미회수 위험을 원(₩) 단위 기대손실로 환산하고, 전세·월세의 리스크 조정 세후
연비용을 비교합니다. 판정과 계산은 전부 결정론 코드가 하고 LLM은 문서 이해와 서술만
합니다.

---

## 1. 5분 실행

전제: macOS 또는 Linux · Python 3.12 · Node 20+

```bash
# 1) 파이썬 환경 (uvicorn·fastapi 포함, [dev]는 pytest)
python3.12 -m venv .venv                       # uv가 있으면: uv venv --python 3.12 .venv
.venv/bin/pip install -e ".[dev]"               # uv pip install -p .venv -e ".[dev]"

# 2) 프론트 의존성
( cd web && npm ci )

# 3) 기동 — 프론트를 빌드해서 FastAPI가 한 포트에서 함께 서빙한다
./serve.sh                                      # → http://localhost:8000
```

**API 키 없이 그대로 동작합니다.** 국토교통부 실거래가 82만건을 미리 받아 `data/cache.db`에
넣어 뒀습니다(공개 데이터, 개인정보 없음). 키를 넣으면 최신 월을 추가로 당겨오지만,
심사에는 필요하지 않습니다.

개발 모드(핫리로드)로 보려면 `./dev.sh` → http://localhost:5180 (API 문서는 `:8000/docs`).

## 2. 테스트

```bash
.venv/bin/python -m pytest
```

**예상 결과: `506 passed, 53 skipped` — 실패 0건.**

skip 53건은 이 환경에 없는 것을 요구하는 테스트이고, 전부 사유를 찍습니다
(`pytest -rs`로 볼 수 있습니다).

| skip | 몇 건 | 왜 |
|---|---|---|
| 실물 등기부 발급본 | 32 | 발급본에 소유자 성명이 실려 있어 **제출물에서 의도적으로 제외**했습니다(아래 6번) |
| L2 XGBoost 백엔드 | 14 | 선택 백엔드입니다. 배포가 쓰는 건 룰 JSON의 로지스틱 회귀 계수이고, 컨테이너 런타임엔 numpy·sklearn조차 없습니다 |
| OCR(tesseract) | 5 | 스캔·촬영본 폴백. 텍스트 레이어가 있는 등기부에는 필요 없습니다 |
| RAG(fastembed) | 1 | `app.py`(연구용) 전용. 배포 제품 `api/main.py`에 포함되지 않습니다 |
| 픽스처 생성 스크립트 | 1 | 합성 등기부를 다시 만들 때만 씁니다 |

개발 환경에서는 발급본 3건과 선택 의존성이 있어 `576 passed`가 나옵니다.

## 3. 문서에 실린 숫자를 여기서 재현합니다

기술설명서의 헤드라인 수치는 이 테스트가 배포 경로에 고정합니다.

```bash
.venv/bin/python -m pytest tests/test_headline_numbers.py -v
```

| 기술설명서의 주장 | 이 테스트가 고정하는 값 |
|---|---|
| 전세 921만원 / 월세 508만원 | `test_annual_totals` |
| 월세보다 연 414만원 비싸다 | `test_wolse_is_cheaper_by_414man` |
| 미회수 기대손실 442만원 = P 4.19% × LGD 52.7% × 2억 | `test_expected_loss_and_its_factors` |
| 밴드 35만~4,418만(125배)에서도 부호가 유지된다 | `test_band_is_125x_and_keeps_its_sign` |
| 항목별 분해 4줄 (120·279·80·442만원) | `test_breakdown_rows` |
| **화면이 문서와 같은 숫자를 낸다** | `test_web_ui_payload_prints_the_documented_number` |

마지막 줄이 나머지와 다릅니다. 위 다섯 개는 계산 함수를 직접 호출하는데, 이건 **웹 화면이
실제로 보내는 요청 본문을 그대로 POST**해서 응답을 확인합니다. 문서가 "화면을 옮겨 적었다"고
말하는 근거가 그 자리에 있어야 하기 때문입니다 — 시세를 반올림해 적었다가 문서와 화면이
1만원 갈라진 적이 있고, 그때 문서가 인용한 값은 제품이 만들지 않는 입력이었습니다.

같은 입력에 같은 출력이 나오므로 직접 검산할 수 있습니다. 조건은
관악구 빌라·전용 40㎡·전세 2억 대 월세(보증금 2,000만 + 월 55만)·선순위 채권최고액 1.2억·
4년 거주, 만 27세·월소득 280만·자산 2,000만·중소기업 재직·무주택 세대주입니다.

## 4. 어디를 보면 되는가

읽는 순서를 계산의 흐름대로 뒀습니다.

| # | 파일 | 무엇 |
|---|---|---|
| 1 | `src/onjeon/register/parse.py` | **L1** 등기부 PDF 파싱. 취소선(도형) 제거 · OCR 폴백 · 문서 종류별 절 분리 |
| 2 | `src/onjeon/l2/model.py` · `rules/risk_model_2026-08.json` | **L2** 로지스틱 회귀 P(사고). 계수는 룰 JSON, 추론은 stdlib |
| 3 | `src/onjeon/l3/risk.py` | **L3** 보증금 미회수 위험의 **단일 정의**. P → LGD → E[Loss] |
| 4 | `src/onjeon/l3/engine.py` | **L3** 세후 비용. 세율은 전부 구간표(`bracket_fee`) |
| 5 | `src/onjeon/l3/eligibility.py` · `recommend.py` | **L3** 자격 판정 + **미자격 반증**(어느 조항에서 얼마 초과) |
| 6 | `src/onjeon/decision.py` | 배포 오케스트레이터 — 전세 vs 월세 비교의 진입점 |
| 7 | `api/main.py` | REST 4개 엔드포인트 + `web/dist` 서빙 |
| 8 | `src/onjeon/rules/` | 세제·상품·금리·낙찰가율 룰 JSON. **버전 태그(YYYY-MM)와 원문 인용이 들어 있다** |
| 9 | `src/onjeon/l4/register_explain.py` | **L4** LLM 서술. 실패하면 `None`을 돌려주고 화면은 그대로 돈다 |

`src/onjeon/l3/register_risk.py`는 `risk.py`와 **다른 축**입니다 — 등기부에 *적힌* 권리
제한(가압류·경매개시·신탁)의 등급이고, 등급이 🟢여도 전세가율이 높으면 E[Loss]는 큽니다.
두 축을 섞지 않은 것이 설계입니다.

   폴리곤 대신 버블로 갔습니다(경계를 억지로 맞추면 없는 정밀도를 주장하게 됩니다).

   금융지원 추천이 나옵니다.

## 6. 제출물에서 제외한 것과 이유

| 제외 | 이유 |
|---|---|
| `data/fixtures/real_registers/` | **실물 등기부 발급본 3건. 소유자 성명이 실려 있어 제외했습니다.** 이것 때문에 테스트 32건이 skip됩니다 |
| `.env` | API 키. `.env.example`에 필요한 키 이름만 남겼습니다 |
| `.venv/` · `web/node_modules/` | 재설치 대상 |
| `web/dist/` | `serve.sh`가 빌드합니다 |
| `data/qdrant/` | RAG 연구용 인덱스. 배포 제품(`api.main`)에 포함되지 않습니다 |

`data/cache.db`(83MB)는 **포함했습니다** — 이것이 없으면 API 키 없는 환경에서 시세 화면이
빈 채로 뜨고, 프로토타입이 고장난 것처럼 보입니다.

## 7. 선택 사항 — LLM

L4는 선택 경로입니다. `GEMINI_API_KEY`를 `.env`에 넣으면 등기부 등급에 해설 한 문단이
붙고, 없으면 붙지 않습니다. **나머지 결과는 완전히 동일합니다** — 숫자는 LLM이 만들지
않기 때문입니다.

`app.py`(Streamlit)는 RAG·3안 비교 **연구용**이고 배포 제품이 아닙니다. 심사 대상은
`api/main.py` + `web/`입니다.

## 8. 알려진 한계 (기술설명서 22쪽에 동일하게 적었습니다)

- 등기부 밖의 위험(임대인 국세 체납, 미신고 선순위 임차인)은 구조적으로 못 봅니다.
- 사고확률 계수가 시군구 집계 보정이라 거칩니다 → 점추정 대신 밴드를 냅니다.
- 시세는 지역 평균 추정치입니다. 특정 호실 시세가 아닙니다.
- 현재 범위는 서울 25개 구 · 상품 룰 7종. 그 밖은 계산 자체를 막습니다.
- 스캔·촬영본과 아파트·오피스텔 **실물** 발급본이 아직 없어 그 두 경로는 합성 픽스처가
  근거입니다.

법률 자문이 아니라 정보 제공입니다.
