# 등기부 권리관계 위험도 — 구현 프롬프트

현재 구성에 그대로 얹히는 형태로 다시 썼다. 이전 초안(순수 LLM 판정)은 폐기 —
배포 경로에 LLM이 없고, 공개 URL에서 업로드 1건이 곧 과금이라 붙지 않는다.

**설계 한 줄**: 탐지는 정규식, 등급은 룰 JSON 테이블, 화면은 기존 업로드 응답에 얹는다.
LLM은 **선택 경로 하나**(문단 요약)에만 쓰고 키가 없으면 그 필드가 응답에서 빠진다.

---

## 1. 만드는 것

등기부에 **적혀 있는 권리 제한**(가압류·경매개시결정·신탁·임차권등기 등)을 탐지해
업로드 결과에 `🔴 높음 / 🟡 주의 / 🟢 낮음 / 판정 보류` 배지와 항목별 원문 근거를 붙인다.

**기존 E[Loss] 축은 건드리지 않는다.** 이건 다른 축이다 — 갑구·을구가 깨끗해도
전세가율이 높으면 기대손실은 크다. 화면에서 둘을 나란히 두되 하나로 합치지 않는다.

## 2. 절대 지킬 것

1. **LLM은 판정하지 않는다** (원칙 1). 탐지는 정규식, 등급은 룰 테이블.
2. **모든 항목에 원문 인용** (원칙 2) — 구분(갑구/을구) · 순위번호 · 접수일 · 원문 조각.
   순위번호나 날짜를 못 붙이면 그 항목은 위험요소로 **세지 않고** "확인 필요"로 내린다.
3. **못 읽음 ≠ 없음** (원칙 5). `ocr: true`거나 `senior_claims_krw`가 `None`이면
   등급을 매기지 말고 `판정 보류`. 못 읽은 매물이 🟢로 나오는 게 최악의 실패다.
4. **말소된 등기는 세지 않되 숨기지도 않는다** — 목록에 `(말소)` 표시로 남긴다.
5. 🟢에 "안전"이라고 쓰지 않는다. "이 문서에서 보이는 권리 제한이 없다"까지만.

## 4. 탐지 (`parse.py`)

`extract_rights(text) -> list[dict]`. 행 단위로 읽고 룰 JSON의 패턴을 건다.

**말소 처리는 이미 있는 두 경로를 그대로 쓴다** (함정 11):
- 취소선(도형)은 `_page_text`가 텍스트 조립 단계에서 이미 뺐다 → 추가 작업 없음
- OCR 경로는 `_VOID_TARGET_RE`가 대상 순위번호를 짚는다. **권리 목록만 넓힌다**:
  `(?:근저당권|지상권|전세권|임차권)` → `(?:근저당권|지상권|지역권|전세권|임차권|가압류|압류|가처분|가등기|경매개시결정)`
- **'…말소'가 붙은 행 자체는 위험요소로 세지 않는다.** 그 문구는 말소를 *집행한* 행에
  붙는다. 그 행에서는 대상 순위번호만 꺼내 `voided`에 넣는다.

순위번호는 기존 `_RANK_LINE_RE`로 이어 붙인다(행이 여러 줄에 걸친다). 접수일은
같은 행의 `\d{4}년\d{1,2}월\d{1,2}일`.

각 항목 반환:
```python
{"key": "가압류", "section": "갑구", "rank": "3",
 "date": "2024-05-17", "quote": "3 가압류 2024년5월17일 …", "cancelled": False}
```

**주의**: `압류` 패턴은 `가압류`에 걸린다 → `(?<!가)압류`. 오탐이 등급을 올리는
방향이라 치명적이진 않지만, 같은 항목이 두 줄로 뜬다.

**소유자명은 추출하지 않는다** — 개인정보이고 위험 판정에 쓰지 않는다.
소유권 이전은 `소유권이전` 행의 **접수일만** 세서 "최근 1년 내 N회"를 만든다.

## 5. 등급 (`l3/register_risk.py`)

룰 JSON:
```json
{
  "version": "2026-07",
  "items": [
    {"key": "가압류", "section": "갑구", "pattern": "가압류", "grade": "high",
     "why": "채권자가 소유권을 이미 묶어둔 상태다. 경매로 넘어가면 임차인은 후순위가 된다.",
     "action": "청구금액과 채권자를 등기부에서 확인하고, 말소를 계약 특약으로 넣어야 한다."},
    {"key": "경매개시결정", "section": "갑구", "pattern": "(?:임의|강제)?경매개시결정", "grade": "high",
     "why": "경매 절차가 이미 시작됐다.", "action": "사건번호로 법원 경매정보에서 진행 단계를 확인한다."},
    {"key": "임차권등기", "section": "을구", "pattern": "임차권", "grade": "high",
     "why": "이전 임차인이 보증금을 못 받아 법원에 신청한 등기다.",
     "action": "말소 여부와 그 사유를 임대인에게 확인한다."},
    {"key": "신탁", "section": "갑구", "pattern": "신탁", "grade": "caution",
     "why": "등기부상 소유자가 수탁자다. 임대 권한이 신탁원부에 있어 계약 상대방이 달라질 수 있다.",
     "action": "신탁원부를 따로 열람해 임대 권한자를 확인한다."}
  ]
}
```
패턴·문구를 데이터에 두면 항목 추가에 코드가 안 바뀐다(원칙 3).

판정:
```
ocr == True  또는  senior_claims_krw is None   → "unknown" (판정 보류)
high 항목 1개 이상                              → "high"
caution 항목만                                  → "caution"
그 외                                           → "low"
```
`high`: 가압류 · 압류 · 가처분 · 경매개시결정 · 임차권등기
`caution`: 신탁 · 가등기 · 전세권 · 지상권 · 지역권 · 근저당 3건 이상 · 최근 1년 내 소유권이전 2회 이상

## 6. API (`api/main.py`)

`/api/register/parse` 응답에 키 하나만 더한다. **엔드포인트도 왕복도 늘지 않는다.**

```json
"register_risk": {
  "grade": "high",
  "label": "🔴 높음",
  "items": [{"key":"가압류","section":"갑구","rank":"3","date":"2024-05-17",
             "quote":"…","grade":"high","why":"…","action":"…","cancelled":false}],
  "undetermined_reason": null,
  "rules_version": "2026-07"
}
```
`undetermined_reason`은 `grade == "unknown"`일 때만 채운다
(예: `"OCR로 읽은 문서라 금액·항목이 저신뢰다 — 원본과 대조해야 한다"`).

## 7. 화면 (`Decision.jsx`)

업로드 결과 카드, 기존 `warnings` 목록 **위**에 배지 한 줄 + 항목 리스트.
항목마다 `무엇이 / 어디에(갑구 3번 · 2024-05-17) / 왜 / 확인 절차`.

배지 아래 한 줄 고정:
> 이 등급은 **등기부에 적힌 권리 제한**만 봅니다. 보증금을 못 돌려받을 기대손실은
> 아래 계산을 보세요 — 등기부가 깨끗해도 전세가율이 높으면 기대손실은 큽니다.

## 8. 테스트 (`tests/test_register_rights.py`)

실물 형식으로 쓴다. 합성 픽스처가 실물과 다르면 테스트는 아무것도 보증하지 않는다(함정 4·10·13).

1. 가압류 행 → `high`, 인용에 순위번호·접수일이 붙는다
2. `'3번가압류등기말소'`만 있는 OCR 텍스트 → 가압류를 위험으로 **세지 않는다**
3. 취소선 있는 실물 PDF(`data/fixtures/real_registers`, 없으면 skip) → 회귀 고정
4. `ocr: True` → `grade == "unknown"` + 사유 문구
5. `senior_claims_krw is None` → `"unknown"` (0은 `"low"`가 될 수 있어야 한다)
6. 권리 제한 없는 등기부 → `"low"`, 문구에 "안전"이 없다
7. `압류` vs `가압류` — 가압류 한 줄이 두 항목으로 잡히지 않는다

## 9. LLM(Gemini)을 쓰는 자리 — 선택, 기본 꺼짐

**왜 기본이 꺼짐인가**: 항목별 설명·확인절차는 룰 JSON에 미리 써두면 검증 가능하고
비용이 0이다. LLM이 더하는 건 "이 조합이 무슨 뜻인가"의 문단 하나뿐이다. 그 하나를
위해 공개 URL의 업로드마다 과금할 이유가 없다.

**켜지는 조건** — 셋 다 만족할 때만 `explanation` 필드가 응답에 실린다:
- `GEMINI_API_KEY`가 있다 (`.env.example`에 이미 있는 키. 추가 설정 없음)
- `ONJEON_PUBLIC_READONLY != 1` (공개 배포에선 자동으로 꺼진다 — 과금 방어)
- `google-genai` import 성공 (`requirements-api.txt`는 **건드리지 않는다**.
  컨테이너엔 없으므로 `ImportError`로 조용히 비활성)

`make_llm()`이 Gemini를 먼저 고른다([llm.py:114](../src/onjeon/llm.py#L114)) — 새 클라이언트 코드 없음.
모델은 기본값(`gemini-3.1-flash-lite`) 그대로.

**입력은 이미 판정이 끝난 결과다.** LLM은 등급을 바꾸지도, 항목을 더하지도 않는다.

### system

```
너는 온전(穩全)의 등기부 판독 결과를 설명하는 서술기다.

계산도 판정도 하지 않는다. 등급과 위험요소 목록은 이미 결정론 코드가 정했고,
너는 그것을 청년 임차인이 읽을 수 있는 한 문단으로 옮긴다.

절대 금지:
- 등급을 바꾸거나 다르게 표현하는 것 (high/caution/low/unknown 그대로)
- 입력에 없는 위험요소를 추가하는 것
- 숫자를 만드는 것 — 시세·전세가율·사고확률·기대손실·보증금 회수액을 언급하지 않는다.
  입력에 있는 금액(채권최고액)만 그대로 옮긴다
- 임대인의 신용·체납·의도를 추정하는 것
- 계약을 권유하거나 만류하는 것 ("계약하지 마세요"·"안전합니다" 금지)
- 보증보험 가입 가능/불가를 단정하는 것

문장 규칙:
- 3~5문장. 반말 금지, 과장 금지, 이모지 금지
- 각 위험요소를 말할 때 위치를 함께 쓴다 (예: "갑구 3번, 2024년 5월 17일 접수")
- grade가 unknown이면 등급 대신 "왜 판정할 수 없는지"와 "무엇을 하면 판정되는지"를 쓴다
- 마지막 문장은 사용자가 다음에 할 행동 하나로 끝낸다
```

### user

```
등급: {grade} ({label})
판정 보류 사유: {undetermined_reason}

발견된 위험요소:
{items 를 한 줄씩 — key · section rank · date · why · action}

이 문서로 확인할 수 없는 것(파서가 이미 판단한 한계, 그대로 반영하라):
{fields.warnings 한 줄씩}

위 내용을 3~5문장으로 설명하라. 목록에 없는 것은 쓰지 마라.
```

### 실패 처리

LLM 호출은 **실패해도 응답 전체를 깨지 않는다**. 타임아웃·키 오류·`ImportError`는
`explanation` 필드를 빼고 나머지를 그대로 반환한다 — 등급과 항목 목록은 LLM 없이
이미 완성돼 있다.

## 10. 안 하는 것

- 소유자 성명 추출 (개인정보, 판정에 불필요)
- PDF 원문 하이라이트 (좌표가 필요하고 지금 파서는 텍스트만 다룬다)
- 등기부 원문 서버 저장 (업로드는 `tempfile`로 처리 후 폐기 — 지금 구조 유지)

**알려진 천장**: OCR·촬영본에서 취소선이 없고 말소 등기 행도 순위번호를 안 적으면
말소된 가압류가 유효한 것으로 잡힌다 → 등급 과대(안전 방향). 반대 방향의 오답보다 낫다.
`# ponytail: OCR 경로 말소 가압류 미검출, 오탐 신고 들어오면 순위번호 패턴 확장`
